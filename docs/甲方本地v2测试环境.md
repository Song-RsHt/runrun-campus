## 分支与交付前提

准备分支是 `prepare/m09-v2-environment`。本次没有推送 GitHub，也没有修改 main。已有本地 `m09/integration` 是 `345968c`；远程分支必须由获得推送授权的交付人员发布本次准备分支到 `m09/integration` 后，甲方才可以使用下面的克隆命令。发布前 GitHub checkout 失败不能解释为本地启动失败。最终提交和验证记录见 `docs/reports/M09-local-environment.md`，实际提交以交付给甲方的完整 hash 为准。

## 从零启动（PowerShell，仓库根目录）

安装 Git、Docker Desktop，启用 WSL2/Linux containers 和 Docker Compose v2 或更新版本。先打开 Docker Desktop，确认以下命令成功。Dockerfile 自带 Maven 和 Java 17，启动后端无需宿主安装 Java；直接运行源码测试时才需要 Java 17/Maven。只有构建前端时需要 Node（满足仓库 Vite 版本要求，建议 22.12+）、pnpm 和 PowerShell 7；普通启动可用 Windows PowerShell 5.1。

```powershell
git --version
docker version
docker compose version
git clone https://github.com/Song-RsHt/runrun-campus.git RunRunCampus
cd RunRunCampus
git checkout m09/integration
git branch --show-current
git rev-parse HEAD
git status --short
Copy-Item .env.v2-test.example .env.v2-test
# 二次确认：只创建本机合成测试管理员；生成随机本地值，拒绝覆盖已有值。
.\tools\initialize-v2-environment.ps1 -ConfirmIsolatedTest
# 本地查看/编辑 .env.v2-test；保留 test、test-admin、固定容器 JDBC 地址和模拟支付。
# 文件含本机随机秘密，不要提交、截图、复制到聊天或发给别人。
docker compose --env-file .env.v2-test -f compose.v2-test.yml up -d --build
docker compose --env-file .env.v2-test -f compose.v2-test.yml ps -a
docker compose --env-file .env.v2-test -f compose.v2-test.yml logs backend
docker compose --env-file .env.v2-test -f compose.v2-test.yml logs migrate
# 等待 postgres/backend 为 healthy；migrate 正常状态是 Exited (0)。
curl.exe -i http://localhost:8082/api/v2/auth/session
.\tools\verify-v2-environment.ps1
# 可选：安装 Node/pnpm 后验证两端同一 API 配置。
.\tools\verify-v2-environment.ps1 -BuildClients
```

私有仓库需要甲方自己的 GitHub 访问权限。不要把 GitHub Token 放入克隆 URL 或仓库文件。`up -d` 退出不等于后端已健康；上面的验收脚本失败会以非零退出。首次需要下载镜像、Maven 依赖，网络慢时构建可能耗时较长。

## 服务与隔离

|服务|用途|对外端口|
|---|---|---|
|postgres|PostgreSQL 16，只创建 rrc_v2_test 及合成哨兵库|不发布|
|migrate|等待数据库健康，按固定清单执行 M00→M08，成功后退出|不发布|
|backend|独立 IdentityApplication + local-v2-test profile，Java 17|宿主 127.0.0.1:8082 → 容器 0.0.0.0:8082|

Compose 项目名固定为 `rrc-v2-local-test`，使用 `v2_isolated` 专用 bridge network、`v2_database` 数据卷、`v2_migration_state` 回执卷和 `v2_evidence` 合成图片卷。数据库不发布宿主端口，未挂载生产数据；运行入口固定容器 JDBC 并关闭微信/真实支付适配器。bridge 本身不提供出站防火墙；选用 bridge 是因为 Docker Desktop 的 internal-only 网络可能不发布 localhost 映射。下载镜像/依赖需要网络。不要叠加旧 compose、env_file、生产配置或 external network。固定项目名用于避免从不同目录误启动重复环境；同机第二套测试必须显式另设项目名及宿主端口，当前自动脚本仅验收 8082。

数据库、迁移回执与合成图片卷必须一起保存、恢复或清理；禁止只删除其中一个。图片根目录固定注入 RRC_EVIDENCE_ROOT=/app/evidence，后端以非 root 用户读写该专用卷。数据库用户是本机新建测试角色，不复用现有账号。PostgreSQL 镜像的 POSTGRES_USER 具有容器数据库管理权限，仅用于隔离测试，不能照搬到共享或生产部署。

## 环境变量统一入口

唯一 Compose 输入是被 gitignore 忽略的 `.env.v2-test`。示例只含占位符，初始化脚本在本机生成独立随机值且不打印。

|变量|要求|
|---|---|
|RRC_V2_JDBC_URL|固定 jdbc:postgresql://postgres:5432/rrc_v2_test；其他地址启动拒绝|
|RRC_V2_DB_USERNAME|本地独立数据库用户名，默认 rrc_v2_local|
|RRC_V2_DB_PASSWORD|本机随机数据库密码，不能复用现有密码|
|RRC_V2_ENVIRONMENT|必须 test|
|RRC_IDENTITY_ENCRYPTION_KEY|独立随机 32 字节 Base64|
|RRC_IDENTITY_HASH_KEY|另一份独立随机至少 32 字节 Base64，不能与加密密钥相同|
|RRC_PAYMENT_MOCK_ENABLED|必须 true，关闭将拒绝本入口启动|
|RRC_V2_ADMIN_PHONE|必须 test-admin，语义为合成登录标识，不是真实手机号|
|RRC_V2_ADMIN_PASSWORD|本机随机测试密码，16–72 字节，不写入仓库|
|RRC_V2_BOOTSTRAP_CONFIRM|必须 CREATE_ISOLATED_TEST_ADMIN，显式确认创建本地合成管理员|

镜像以 `-Pv2-identity` 打包，main 为 `com.zhangxuan.runrunv2.IdentityApplication`，只扫描 v2。它通过 `spring.config.name=application-v2` 排除旧 `application.yml` 和 dev 配置，再加载 `application-v2-local-v2-test.yml`。测试 overlay 固定关闭微信 HTTP 网关，固定 synthetic-local-app；订阅网关同样不会访问微信。普通 `application-v2.yml` 的现有监听默认不变；本编排明确用 0.0.0.0:8082 覆盖，不能只监听容器 127.0.0.1。

`application-v2-test.yml` 继续专供 JUnit（随机端口、测试类提供合成 adapter/密钥、Testcontainers 数据源），不是 Docker 的 HTTP 启动入口。本次没有把它与旧 Spring 配置混合。上述三项 JDBC 变量和 identity 密钥由统一 env 注入 Compose 的 HTTP v2 入口；宿主直接运行 JUnit 时用既有 isolated runner，不把 env 文件当成 JUnit 自动加载文件。

## 初始化、迁移与重启

唯一运行清单为 `deploy/v2-test/migrations.txt`，依次：

```text
M00 0001 → M01 0002/0003 → M02 0100 → M03 0200 → M04 0300
→ M05 0004 → M07 0006/0101 → M06 0500 → M08 0007 → M09 修复 0701
```

M00–M08 的 11 份迁移后，追加 0701 审计修复，共 12 份。0701 恢复被 0101 遗漏的 M01/M02 既有审计动作，使全链空库管理员初始化可用；不修改旧 up 文件。修复迁移拒绝重复或异常约束，保留修复后审计记录时拒绝回滚。完整文件名见清单。前置顺序沿用 M09 已测试 runner，不能按文件名字典序排序。`0600/0700` 是仓库保留的另一套通知迁移设计，不与 M09 的 `0007` 混跑；不会读取 `public` V1–V43，不启用 Flyway、baseline、clean 或 Hibernate 自动建表。

每个原 SQL 自带事务和重复执行拒绝。新 runner 每次校验已完成文件 SHA-256，回执匹配则跳过，未完成才执行；因此正常保留卷重启可复用，直接再次执行 SQL 仍应失败。回执文件不进入业务 schema，不放宽原 SQL 的空库或回滚门禁。如果 SQL 已提交但回执尚未写入时断电，下一次会拒绝重复迁移，须按故障说明处理，禁止自动猜测 baseline。

旧 public 验证分两层：v2 目标库的 public 必须没有关系对象（启动门禁拒绝旧表）；同一容器另建完全合成的 `rrc_legacy_sentinel.public.v2_test_sentinel`，验收只读检查其固定值未变。单独迁移回归脚本还验证含假 Flyway history/campus_orders 的旧库被 M00 拒绝、重复 SQL 被拒、保留通知阻止回滚和空库逆序回滚。不要把实际旧库接进来做哨兵。

```powershell

Push-Location handover-2026-10-24/RunRunCampusBackend
pwsh -NoProfile -File tools/run-v2-isolated-tests.ps1
Pop-Location
```

## 隔离管理员和会话

首次成功启动且账号库为空时，在同一事务中创建不能交互登录的 controlled deployment identity，再创建 test-admin 的合成微信身份记录（不调用微信），复用既有 `provisionAdmin/changeAccess` 服务提升并启用 ADMIN；理由固定为 `Isolated synthetic local test fixture`，记录初始化、版本变更及授权审计。没有匿名初始化 API。只有 local-v2-test profile、固定本地 DB、test 标识、模拟支付和显式确认同时成立才运行。

后续启动只检查既有合成管理员和审计，不重置密码、不自动恢复已停用资格。密码、身份密钥必须保留原 env 值；改动不会自动轮换已有数据。其他非空账号库拒绝自动初始化。要重新创建本地测试数据，先确认本机合成数据可以丢弃，再 `down -v`。

管理员登录标识为 test-admin，密码在本地 env 文件中自查；管理端使用 `/api/v2/auth/password/login`。自动验收脚本演示登录→session→通知→退出→失效校验，全程只在内存持有 Token，不写磁盘、不输出。v2 会话保存于 `runrun_v2.user_sessions`，只保存独立密钥摘要，不复用旧 JWT/session。

本环境不提供真实微信注册，不使用真实手机号。小程序现有登录 UI 有手机号格式和隐私接口依赖，不能把 test-admin 直接塞入手机号表单；小程序完整登录/业务真机验收不在本次构建验证内。需要合成普通用户/骑手及专用 UI 的后续验收，应另做受控 fixture，不解除微信禁用、不使用真实手机号绕过。当前提供的测试账号用于管理端与 API 环境验收。

## Nginx / HTTPS 示例和 404 排查

`deploy/nginx/api-test.v2.conf.example` 只是示例，本次不安装、不 reload Nginx、不修改现网域名。由甲方在隔离测试机器上提供 `api-test.runruncampus.cn` 的 DNS、证书和 HTTPS 配置；证书、私钥永不保存到仓库。本地直接 localhost 即可，不需要公网域名。

宿主 Nginx upstream 指向该测试机器的 `127.0.0.1:8082`；容器 Nginx 的 loopback 指自身，必须加入隔离网络并改为 `backend:8082`，不要指向旧服务 8080。`location ^~ /api/v2/` 的 proxy_pass 不加 URI/尾斜杠，以完整保留 `/api/v2/`。禁止把这一前缀交给旧 v1 upstream 或 SPA fallback。

甲方部署前先验证本地：

```powershell
curl.exe -i http://localhost:8082/api/v2/auth/session
# 在甲方安装示例、配置证书且 nginx -t 通过后再验证：
curl.exe -i https://api-test.runruncampus.cn/api/v2/auth/session
```

两处未登录均应 401；公网仍 404 而 localhost 为 401，重点检查 DNS 所在主机、server_name、配置是否载入、upstream 是否旧 8080、proxy_pass 是否剥掉前缀和是否命中其他 location。本交付不会自动修复当前 api-test 域名上的 404，也没有运行公网检查。

## 故障排查

|现象|检查与处理|
|---|---|
|Docker API / Linux engine 不可用|打开 Docker Desktop、启用 Linux containers，先让 docker version 的 Server 正常|
|数据库未就绪|ps -a、logs postgres；磁盘空间/初始化密码；不要关闭健康检查强行启动 backend|
|迁移失败|logs migrate；核对固定清单、文件 checksum 和配套测试卷；失败不会启动 backend；本机合成数据可弃时 down -v 后重建|
|SQL 提交后回执丢失|拒绝自动 baseline；保留故障卷用于本地检查，或确认本机测试数据可弃后配套重建；不能盲目补回执|
|密钥缺失/格式错误|Compose 的必填变量或 IdentitySecrets 会拒绝；必须两个独立 Base64 随机密钥，不能复制示例占位符|
|端口占用|Get-NetTCPConnection -LocalPort 8082；确认进程用途，不强停不明服务；如改端口同步文档/客户端/验收脚本|
|后端 404|确认端口 8082、正确 HTTP 方法、v2 main/Profile、migrate 成功；查看 backend 日志中的应用名和监听地址，禁止切回旧 jar|
|public Flyway 被错误启动|立即停止本测试 Compose；说明运行了旧 compose/main 或混入配置；恢复本入口，不能删除旧迁移或设置 baseline 绕过|
|管理员初始化失败|只允许 test-admin、显式确认、空账号库；既有密码/资格/审计不同则拒绝自动修改；保留原 env 或重建本地测试卷|
|前端 Network 跨域失败|只用 RRC_LOCAL_ADMIN_ORIGIN 配置的精确 Origin（默认 http://127.0.0.1:5173）；确认调用 8082 和 local-v2-test；不要关闭后端权限检查|
|后端启动异常|日志可能含依赖错误，只在本地查看，不对外粘贴环境变量；使用 ps -a 与 logs backend/migrate 定位失败阶段|

## 停止、清理和回滚

```powershell
# 保留数据库、迁移回执和本地 env，可再次 up。
docker compose --env-file .env.v2-test -f compose.v2-test.yml down
# 仅当本机合成测试数据可以全部丢弃：同时清理本项目三个测试卷。
docker compose --env-file .env.v2-test -f compose.v2-test.yml down -v
```

不使用 docker system prune、不删其他项目、不运行生产迁移。源码回退使用 `git revert <本交付提交>`；有业务/证据的数据库不强跑 down SQL，不使用 CASCADE。手工空库回滚按清单逆序，原回滚脚本的依赖/数据拒绝规则仍有效。本环境优先通过本项目 down -v 后从空库重建恢复，不恢复真实备份。
