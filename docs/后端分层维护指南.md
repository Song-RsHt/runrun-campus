# 后端分层维护指南

适用工程：`handover-2026-10-24/RunRunCampusBackend`。`com.zhangxuan.runrunv2` 与 `com.zhangxuan.runruncampus` 分别保持独立启动、扫描、账号、数据模型及运行环境。业务定义仍以阶段一业务基线、专题规则和数据模型与接口契约为准。

## 目录与定位

参照只读的苍穹外卖工程，业务代码按技术层集中组织。Controller 采用本项目更明确的平铺要求，不保留参考工程的 admin/user 子包，也不保留旧的 order/payment 等业务子包。

|目录|维护职责|
|---|---|
|`controller`|HTTP 路由、请求绑定、认证上下文、状态码及响应头；依赖业务接口|
|`service`|业务能力接口；中文 Javadoc 说明目的、参数、返回值和重要前置条件|
|`service/impl`|实现业务接口，通过构造器注入协作者；保留事务、锁、幂等和状态推进|
|`mapper`|JdbcTemplate SQL、明确参数及行映射；使用调用方事务绑定的连接|
|`repository`|legacy 既有 JPA Repository；不额外包装为同名 Mapper|
|`dto`|HTTP 请求；保留 Jackson、校验注解和构造器行为|
|`vo`|HTTP 响应及响应中的分页类型；保留字段、层次、空值和序列化规则|
|`entity`|持久化实体，尤其 legacy JPA 映射|
|`model`|内部投影、二进制载荷、业务快照和值；不堆入巨型 Models 容器|
|`enums`、`constant`|业务枚举和真正常量；协议取值不得随中文注释调整|
|`exception`、`handler`|中立业务失败，以及 HTTP 异常映射|
|`security`、`config`|安全策略、应用配置和严格 JSON 绑定|
|`integration/<职责>`|微信、支付、推送、存储、HTTP 上传适配及后台工作器|
|`task`|薄调度入口；调用业务接口或工作器代理，保留既有注册和启用条件|
|`bootstrap`|受控主机命令、初始化及启动校验|

各类型包直接存放类；只有 `service.impl` 和确需渠道或职责隔离的 integration 子包例外。不创建空包；新旧应用不得合并进同一业务包。同一应用有重名时，使用 `AdminMfaVerifyRequest`、`CreateOrderRequest` 等明确类名。

从路由沿构造器追踪实现，例如：

* `POST /api/v2/orders` → `controller.OrderController` → `service.OrderService` → `service.impl.OrderServiceImpl` → `mapper.OrderMapper`、`mapper.OrderStore`。`OriginalPaymentWriter` 在同一订单事务内写入原始支付义务；其现有实现由 `PaymentServiceImpl` 提供。
* `GET /api/v1/admin/orders/{id}/delivery-proof` → `AdminOrderDeliveryProofController` → `AdminOrderDeliveryProofService` → `AdminOrderDeliveryProofServiceImpl` → `OrderRepository`、`OrderProofRepository` → `OrderProofStorage`。Controller 保留权限入口及 no-store/nosniff 响应，内部二进制载荷不暴露存储键。
* legacy 指挥台 → `AdminCommandCenterService` → `AdminCommandCenterServiceImpl` → `AdminCommandCenterMapper`。权限筛选和重复读快照留在业务实现，队列查询及计数留在 Mapper。

本轮全类映射、接口/Impl 对照及验证结果见 [苍穹风格返工报告](reports/Backend-sky-style-refactor.md) 和其映射附件。旧 `backend-layered` 报告只记录上轮历史结构。

## 接口、事务与边界

业务 Service 统一使用接口和 Impl。接口不声明 Servlet、ResponseEntity、MultipartFile 或数据库实现类型；实现使用 `@Service`、构造器注入及 `@Override`，注入其他业务服务时依赖接口。不要为 private 辅助方法新增接口方法，也不要为 Worker、Calculator、Storage、Gateway 或工具类机械制造 Impl。

事务放在实现类或实现方法，不改变传播、隔离、回滚条件和锁顺序。不得通过新包装层造成同类自调用绕过事务。移动类时同步所有 import、注解类引用、JPQL 中的枚举全名及测试引用；编译器不会检查 JPQL 字符串中的旧路径。

legacy 的 `BusinessFailure` 保存原状态分类和提示，由 `ApiExceptionHandler` 恢复原状态码、`message` 正文和 429 响应头。它不继承 Spring Web 异常。双因素服务原先针对 `ResponseStatusException` 的不回滚规则同时覆盖新业务异常，并按完整类名保留对加密协作者原异常的匹配；不能因清理 import 删除这一兼容条件。

上传入口保留 MultipartFile，使用各自应用的 `integration.web.MultipartUploads` 延迟适配为 `model.UploadSource`。适配时不读取字节、不提前校验；业务仍按原顺序完成鉴权、状态/版本检查、加锁和文件读取。不要把文件预读到 Controller 改变失败顺序。

Mapper 不开启独立事务、不自行取连接或提交。SQL 保留 Java 17 文本块，按列、子句、条件及绑定顺序排版，方法名表达查询、插入或状态更新的真实含义。JSON/行投影中的混合值可以保留 `Map<String,Object>`；标识、状态和金额入参必须使用契约对应的明确类型。

## 中文可读性与排版

统一四空格缩进，一行一条语句，控制块使用花括号，import 明确且无闲置项。字段按常量、依赖及运行状态合理成组，不在每个同类依赖字段之间机械空行。保留 record 的不可变性，不引入 Lombok、MyBatis、MapStruct 或新格式依赖。

类注释说明职责及边界；Service 接口说明业务含义和必要失败条件；复杂实现说明锁、事务、幂等、补偿及安全判断的原因。Mapper 对锁及版本条件作必要说明，Task 说明调度职责，启用条件以现有注解和工作器门禁为准。错误码、协议标识和第三方字段保持原值。

人工抽查完整调用链，包括入口参数、接口文档、实现业务步骤和 SQL 绑定。不得用“中文字符存在”“格式工具通过”代替可读性审查，不加空标签或无信息的逐行注释。

## 运行与验证

Java 17、Maven、Docker 和 PowerShell 7 为现有验证工具。在后端目录运行：

```powershell
mvn -B -ntp clean test
mvn -B -ntp -Pv2-identity -DskipTests package
pwsh -NoProfile -File tools/run-v2-isolated-tests.ps1
```

打包命令的跳过测试仅用于已完成回归后的制品构建，不替代完整测试。隔离 runner 递归枚举测试包声明及完整类名；移包后不能改成会漏掉测试的根包通配符。真实 PostgreSQL/Testcontainers 测试继续保留，不删除、跳过或降低断言。

默认主类是 `com.zhangxuan.runruncampus.RunRunCampusBackendApplication`，保留 legacy JPA/Flyway 和既有数据库配置；仅使用隔离本地数据。v2-identity profile 主类是 `com.zhangxuan.runrunv2.IdentityApplication`，只扫描 v2 并排除 JPA/Flyway 自动配置。不得扩大扫描到 `com.zhangxuan`。旧 V1–V43 不改写，也不作为 v2 初始化链。

在干净 clone 的仓库根目录执行隔离环境检查：

```powershell
Copy-Item .env.v2-test.example .env.v2-test
pwsh -NoProfile -File tools/initialize-v2-environment.ps1 -ConfirmIsolatedTest
docker compose --env-file .env.v2-test -f compose.v2-test.yml up --build -d
pwsh -NoProfile -File tools/verify-v2-environment.ps1
pwsh -NoProfile -File tools/verify-v2-local-migrations.ps1
```

初始化只生成 Git 忽略的合成测试凭据且拒绝覆盖已有值，不打印或提交 env。Compose 仅将 API 绑定本机 8082，数据库不发布端口。验证包含管理员登录、session、通知、三种资质列表查询、登出、私有卷权限和旧库哨兵。模拟功能仍受现有环境门禁约束；生产、真实支付及部署需要另行指令。

`BackendLayeringTest` 检查包位置、47 组业务接口/实现、构造器依赖、HTTP/持久化方向、应用隔离、8 个调度的表达式与条件，以及双因素失败回滚规则。既有 Surefire 退出等待告警单独记录，不通过关闭测试或业务调度掩盖。

金额仍以分计算，保全优先于清理，outbox 的领取、租约、网络调用和完成回写边界不变。业务修复、结构重构和迁移分别评审；环境阻塞如实登记。本轮完成后只提交独立 QA，不自行推送、合并或替换已发布版本。
