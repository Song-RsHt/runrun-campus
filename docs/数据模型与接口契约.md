## C01 身份与管理员

业务身份只有 USER、COURIER、ADMIN。v2 ADMIN 不再细分客服、运营、审计等岗位。下表是动作边界，不是新增角色矩阵。

| 身份 | 可执行动作 | 必须满足的限制 |
|---|---|---|
| 普通用户 | 本人下单、支付、取件前申请调整、确认、取消、登记售后、查看本人订单 | 微信验证/绑定；数据归属；补款未结清不得读取送达照片和位置 |
| 骑手 | 本人资质申请/上传、本人任务与新系统任务/订单查询；有接单资格时接单、取件、送达、提交规格证据、到场打卡、释放或确认交接 | 资质和本人历史不要求已获接单资格；履约写须有资格、当前任务及名额；送达后仅保留下述有限调整权限；其他旧任务只读 |
| 已启用 v2 管理员 | 骑手资质查看/审核及学生证受控读取、审核调整、关闭未决调整、长期结案转欠款、退款/赔付、分配、冻解、逐单付款登记、免债、终止追偿及调查取证 | 状态、余额、证据、理由、审计、适用 MFA；不能授予 v2 管理资格 |
| 资格管理身份 | 启用/停用 v2 管理员 | 仅后端确认的既有 SUPER_ADMIN 或项目所有者指定受控部署身份；不是普通 v2 ADMIN 的附带能力 |

送达后的有限写权限：仅实际完成最近一次有效送达的骑手，且其任务为 DELIVERED、未被后续重新履约或交接替代，订单为 DELIVERED_PENDING_CONFIRMATION 时，可通过 A19 申请调整及通过 A35/A14 上传、登记 SPECIFICATION 证据。后端每次按订单和任务记录判定，不使用客户端“当前骑手”标志。此权限不把任务改回 ACTIVE，不恢复取件、送达或 ARRIVAL/DELIVERY 定位写入，不占名额。RELEASED、HANDED_OVER、CANCELLED 任务及被替代的旧骑手无此权限；订单 EXCEPTION、COMPLETED、CANCELLED 时拒绝该写入。A24 取消后到场补贴申请仍按其独立条件执行，不属于恢复履约权限。

`app_users` 保留现有账号和旧角色；V44 添加 `v2_admin_enabled BOOLEAN NOT NULL DEFAULT FALSE`、`v2_admin_security_version BIGINT NOT NULL DEFAULT 0`。只有原身份 ADMIN 可启用；不会因历史 SUPER_ADMIN 身份自动启用 v2 业务权限。每次 v2 后台请求查询当前启用状态与安全版本，停用立即失效，不仅检查登录时令牌。

首个管理员由项目所有者授权的受控部署脚本或既有 SUPER_ADMIN 手工执行同一启用服务，持久化审计；无管理员时不开放匿名初始化、自助提权或公共“首个账号”入口。部署身份为秘密管理中明确配置的受控执行身份，不由手机号、请求参数或前端标志推导。启停理由必填，资格管理不得绕过旧 SUPER_ADMIN 的认证及 MFA。旧系统最后超管保护继续适用。

新后台在现有管理端新增 `/v2-admin` 路由与独立导航、API 客户端。业务入口依 ADMIN 身份和启用标记，不依旧 23 项权限；资格管理入口另按资格管理身份校验。旧 v1 权限菜单、ORDER_FORCE_COMPLETE 和溯源双人核验规则不变。退款、赔付、免债、结案、付款登记前端二次确认；后端理由、授权、状态检查必做，不能信任前端确认标志。

单管理员、无金额上限、无双人审批仅适用于阶段一模拟资金；阶段二真实资金上线前必须重新评估。五角色设想见[后台五角色升级方案](后台五角色升级方案.md)，不提前启用。

## M44 核心模型

以下为 V44 目标清单。公共列约定：各实体 `id BIGINT PK`、`created_at TIMESTAMPTZ NOT NULL`；可变聚合另有 `updated_at TIMESTAMPTZ NOT NULL`、`version BIGINT NOT NULL DEFAULT 0`。表中未标“可空”的字段均 NOT NULL；外键只能指向已创建表；JSONB 快照必须后端校验键和类型。索引包含所有外键，清单额外列出查询/唯一索引。不复用旧订单表承载新单。公共 version 是乐观并发版本，从 0 开始，每次成功更新聚合递增，与固定的 order_flow_version 不同；expectedVersion 匹配的是 version，冲突拒绝且不产生业务副作用，幂等重放不再递增。

M44-14 复用 `admin_audit_logs`，V44 增加 `metadata JSONB NOT NULL DEFAULT '{}'` 与 `request_id TEXT`（旧行可空、新v2动作必填，部分唯一索引按动作/操作者/请求去重）。资格启停动作统一 `V2_ADMIN_ACCESS_CHANGED`、目标 `APP_USER`，metadata 记录 oldEnabled/newEnabled、oldSecurityVersion/newSecurityVersion、actorKind、reason。受控部署身份必须映射实际 ADMIN 系统账号供 administrator_id 关联，其凭据受控且不开放普通用户登录；不能用空操作者、伪造用户ID或写文件代替持久审计。该部署身份不自动获得日常v2业务权限。其他新增动作按模型版本扩充 action 与 target_type，保留所有旧值。

应用层证据模块从 V44 开始承担到期清理任务，不能等到 V47。保留期限以迁移方案第 4 节为准；同资源所有生效保全解除前不删。新增保全与清理锁同一订单，删除前事务复查、标记 DELETING 并禁止建立新访问地址；实际删除期间保持该订单排他执行（删除执行器与保全服务共用数据库 advisory lock）。对象存储失败记 FAILED、重试，不提前标记 DELETED；成功后移除精确位置正文、撤销访问并写审计。已进入删除中的售后必须等待删除动作完成后重新评估可用证据，不能宣称已保全实际已删除的资料。

### 骑手资质共享状态与证据生命周期

M44-15 是现有资质表的增量扩展，不另建 v2 资质事实。V44 为现有照片分配不含存储键的稳定资源标识，保留原照片、审核和接单资格，不重审、不回填新订单表。旧字段中的姓名、学号、学校和有效期只作历史兼容；v2 申请不采集这些字段，不新增有效期或到期自动停权。当前代码使用照片审核且未启用上述字段校验，仅是本次规则选择的依据，不表示 v2 已实现。

新注册 COURIER 创建未获接单资格的账号，可以登录、查询/提交资质和上传学生证；旧 COURIER/ADMIN 账号恢复仍需人工核验，两者不能混为一条自动恢复分支。首次申请或无既有资格者只有批准后 eligible=true；已获资格者重新申请时保留资格，驳回本次重申请不自动撤销既有资格。审核状态 status 与接单资格 eligible 分开返回；照片依政策删除也不撤销资格。没有资质行但原账号已被批准的兼容情况仍按原资格返回，不伪造审核材料。

v1/v2 所有申请、重申请、换图、审核、清理及照片引用变更共用账号/资质锁和同一 version，每次成功更新递增；v1 请求体不强制新增 expectedVersion，但其服务写入必须递增共享版本，不能继续使用绕过共享服务的旧写路径。v2 修改已有资质须带 expectedVersion；审批同时校验待审核状态、申请轮次和当前照片资源标识，管理员先读取得到的 version 在换图、重申请或其他入口审核后即失效。状态变化冲突返回 CERTIFICATION_STATE_CONFLICT，版本冲突仍用 ORDER_STATE_CONFLICT。首次创建无行时锁账号并靠 courier_id 唯一约束防重。PENDING 不接受另一次申请；NOT_APPLIED/REJECTED/APPROVED 可按同一记录重新申请，只有本次申请之后上传的有效学生证可用于批准。

照片为真实 JPEG/PNG，最大 8 MiB（8,388,608 字节），同时检查声明类型、文件内容并确认可被图像解码器识别；只允许本人 PENDING 申请上传。A38 使用受控 multipart 上传，不借用仅供订单证据的 A35。学生证对象私有，A39 仅启用管理员可读，读取写审计且响应 Cache-Control: no-store；不返回对象键或公开地址。无本次有效照片返回 PROOF_NOT_READY，已依政策删除的照片返回 PROOF_EXPIRED。

保全和删除的排他主体为带类型的订单或资质标识：订单资源共用订单锁；学生证共用资质锁及以 CERTIFICATION 为命名空间的 advisory lock，不伪造 order_id。资质保全覆盖该记录当前及尚未清理的旧照片；重申请、换图、批准不能绕过保全直接删除对象。移出当前引用的对象及待删对象先在 M44-12 持久化资源标识、内部存储键和清理状态，再替换引用；按迁移方案原保留期限计算 delete_after，未审材料不凭替换动作捏造审核时间，待本轮审核后确定期限。原审核过的照片沿用其原审核时间，保全延后清理而不重置普通期限。删除前再次检查所有保全，标记删除中并禁止该资源读取，存储删除成功后才清理匹配该resource_id的照片引用并写 SUCCEEDED，不能清除后续换入的新照片；成功审计保留资源标识并清空已不再需要的内部存储键。执行中状态为DELETING，读取/新增保全遇到该资源执行锁占用时等待完成或返回EVIDENCE_DELETION_IN_PROGRESS，不将等待队列里的REQUESTED误报为已删。失败记 FAILED，保留可重试引用，不提前宣称已删。学生证删除、读取和重申请不能通过旧 v1 清理任务绕过这些约束；旧任务须调用共享证据服务。

V44 同步扩展实际 action/target_type 约束，资质申请/上传/读取分别使用 COURIER_CERTIFICATION_SUBMITTED、COURIER_CERTIFICATION_PHOTO_UPLOADED、COURIER_CERTIFICATION_PHOTO_READ，批准/驳回保留既有 COURIER_CERTIFICATION_APPROVED/REJECTED，目标均为 COURIER_CERTIFICATION。所有资质申请/上传/审核及照片引用变更同事务写M44-16事件，读取审计不修改资质version；骑手和系统使用真实actor_kind，系统actor_id可空，不伪造管理员作为actor；删除执行结果另写M44-12；管理员读取/审核进入 admin_audit_logs，metadata 记录理由、requestId、资质版本及照片资源标识，不记录照片正文或存储键。

系统对原款、补款各按平台 floor(amountCents×30/100)、骑手=总额−平台份额分配；降档按原有效分账的目标差额冲减，累计冲减不得超过该来源有效权益，末笔吸收舍入差保证守恒。

无交接、无分配争议，系统将骑手池 100% 自动分配给实际完成骑手；取件前释放旧骑手不获得该单骑手池，到场补贴单列。发生实物交接或分配争议，由管理员按任务确定金额，总额仍是骑手池，不重复生成 70%。重新履约后已有付款、权益变更用版本与独立调整处理，不能覆盖已发历史或再次生成原款分账。未批准人工分配只阻止该单骑手款。

售后登记与阻止完成、默认冻结同事务：该单全部未发放平台和骑手权益均冻结；金额尚未明确不冻结零元。未决案件存在时新产生权益同样纳入，多个案件不逐案释放。全部结案后按定责结果和管理员风险冻结重算，再恢复原结算条件；解除不等于直接可付款。

冻结只阻止平台/骑手权益发放及结算，不阻止已批准用户退款、赔付。已付款不能再冻结，登记应收人工追偿。付款登记与售后/风险冻解锁同一订单及权益聚合，事务检查可发余额、冻结、分配和来源释放条件；并发售后先锁成功则付款被拒，付款先完成则售后记录已付款并转应收。余额不得为负，不自动扣未来日结或微信资金。

原款送达十分钟无未决异议可结，不要求调整结清；补款正常完成无异议后释放，结案后还款检查争议再释放。由付款登记事务检查，不依赖前端按钮。

## S01 状态与一致性

v2 主状态：PENDING_PAYMENT、PENDING_ASSIGNMENT、ACCEPTED、PICKED_UP、DELIVERED_PENDING_CONFIRMATION、EXCEPTION、COMPLETED、CANCELLED。调整：PENDING_REVIEW、PENDING_SUPPLEMENT、PENDING_REFUND、COMPLETED、REJECTED、CANCELLED、TRANSFERRED_TO_DEBT。调整只允许一单一个未终结申请，后续申请基于已生效规格，避免并发价差重复；审核不阻止取送。

全部状态变化锁同一订单聚合。确认完成必须同时：已送达、有效确认窗口、无未结调整、无未决售后；自动完成再要求到期。出现新调整窗口作废，财务结清后重新给完整十分钟；delivered_at 不变。送达后有限权限仅按C01执行；调整与用户确认/自动完成锁同一订单，完成先提交则调整拒绝，调整先提交则窗口失效，不能在订单已完成后追写申请。长期人工结案仅对已送达且补款逾期超过30天，争议一并裁定，转欠款，不伪造付款。审核超24小时只升级，可人工关闭未决调整按原价；未送达仍必须履约。

混合列表投影固定 `flowVersion/orderId/orderNo/createdAt/rawStatus/displayStatus/paymentSummary/debtOutstandingCents`；版本与ID构成资源标识，不以裸 id 混查。服务端授权过滤后 UNION ALL 两源，按 created_at DESC、flow_version DESC、id DESC 做统一游标分页。游标包含查询条件摘要和上述三值，limit 1–100 默认20，响应 items、nextCursor（无则 null）；禁止分别分页再前端合并。v1 只读投影与新流程写接口隔离。

| 来源与原始状态 | 统一展示状态 | 条件/独立标记 |
|---|---|---|
| v1 PENDING_ASSIGNMENT | PENDING_PAYMENT 或 PENDING_ASSIGNMENT | 仅 WECHAT_APP 且 UNPAID 显示待支付；现金/人工收款保留待接单并标支付方式及进度；PAID 正常待接单；退款等不匹配组合标 REVIEW_REQUIRED |
| v1 PENDING_REASSIGNMENT | PENDING_REASSIGNMENT | 显示旧支付进度；异常付款组合额外挂 REVIEW_REQUIRED，不擅改状态 |

`paymentSummary` 含 method、originalStatus、supplementOutstandingCents、refundStatus；历史人工收款另含 manualPaymentStatus。未连接生产库，不能声称不存在“待接单但未付”的历史组合；迁移前按支付方式与状态交叉统计。只读兼容详情允许历史订单；普通 v2 单详情/写入口在归属校验后明确版本不匹配。

## A01 接口公共约定

下表所有路径加 `/api/v2`。JSON 成功对象按表中字段返回；创建返回201，其余成功200，拒绝使用 E01。请求中的 `reason` 均为非空说明。已认证业务写入要求 `Idempotency-Key`（同操作者+路由作用域唯一、内容绑定资源和用途），更新现有聚合再带 `expectedVersion`；版本冲突409。A01–03 为认证入口，不要求尚不存在的 actor_id 或订单版本，按微信一次性code/登录票据与身份唯一约束去重，失败后重新获取授权；A07报价为无副作用试算，不要求幂等键和expectedVersion。查询不改变业务状态，受控读取按规定追加访问审计；查询不要求幂等键。证据/微信一次性 code 不存入幂等响应摘要；复放不得再次兑换 code 或生成额外入账。expectedVersion指URL所标聚合，创建新对象不带；绑定、认证、只读及通知已读不要求订单版本。A37首次申请无资质行时不传expectedVersion，重新申请、A38换图及A40审核使用M44-15的资质version；A38的expectedVersion为multipart文本字段。A35/A14/A19的送达后有限写仍使用订单version。只读响应不带不存在的实体版本或虚构订单版本。

认证令牌由后端签发，权限与资源归属先验证再返回版本、照片等细节；未授权对象404，身份不符403。USER仅本人；COURIER履约写按当前任务，送达后有限调整按C01，A24按取消后补贴独立条件；资质及本人任务/订单读取不以已批准为前提；ADMIN为C01启用资格；G为资格管理身份（不要求先有v2管理员）。测试控制路由还要求隔离环境+ADMIN，生产不注册路由。所有响应脱敏；证据读取生成短效地址，读取时仍校验未补款、保全和删除状态。

订单证据读取和学生证读取分别按其订单或资质资源授权；资质保全不开放给骑手作为越权读取入口。

操作引用模型并明确事务族：O=订单聚合锁（含确认、异常、调整）；P=O+支付/退款余额锁；S=O+结算聚合锁；I=账号/绑定/资质锁与唯一约束；C=配置版本锁；R=受控只读。幂等记录与业务提交同事务。所有副作用审计、事件及适用 outbox 同事务，外部通知异步。

### 骑手任务与新系统订单查询

A36的 /courier/tasks 仅查 fulfillment_tasks.courier_id=当前账号，按 created_at DESC、id DESC 做游标分页，支持 OFFERED/ACTIVE/RELEASED/HANDED_OVER/DELIVERED/CANCELLED 过滤；行含 taskId、taskStatus、taskVersion、flowVersion=2、orderId、orderNo、orderStatus、orderVersion、createdAt、allowedActions，不返回其他骑手任务明细。OFFERED 邀请可在未接受时被找回，仍不占容量；无接单资格者可查，但不能因此执行需资格的接单/接受动作。

新系统订单按本人 fulfillment_tasks 关联筛选，按订单去重并使用统一游标分页；不读取旧订单表，不生成旧任务兼容行，不根据姓名或手机号推导归属。

新系统订单响应沿用统一状态和支付映射，增加本人任务摘要；详情先校验本人关联，只给本人证据和履约必要信息。已释放或交接任务仅给本人阶段的脱敏摘要及证据，不给其他骑手材料。不存在 v1 详情、存量收尾或旧支付映射。

所有新增列表沿用 limit 1–100、默认20及 items/nextCursor；游标绑定接口、当前骑手/管理员及过滤条件，跨身份或条件更换须重新查询。资质管理列表按 submitted_at DESC、id DESC 排序并绑定status过滤；详情包含 version，避免审核页面使用未标版本的材料。

certification 响应白名单为 id（未申请可null）、courierId、status、eligible、version（无实体时null）、submittedAt、reviewedAt、rejectionReason、photoUploaded、photoResourceId；时间和未发生字段为null，NOT_APPLIED为无申请投影。photoUploaded仅表示当前适用照片仍可用，不等于eligible；骑手响应不含其他账号材料、对象键、私有地址或历史姓名/学号。管理员详情可附必要的脱敏账号标识和审核者，不复制历史敏感字段。A39读取照片的审计失败则拒绝交付内容。A38幂等快照不存照片字节，复放时再校验当前归属和读取资格，不重新写对象；A40绑定预览时版本及照片资源标识，驳回可无照片但理由仍必填。

### 共享请求结构与关联校验

- `liabilities` 为 `{subjectType: PLATFORM|COURIER|OTHER, subjectId: string|null, amountCents: integer, basis: string}` 数组；骑手必须有ID，其他承担方实名依据受控存放；合计等于本次批准退款/赔付对应责任金额，退款与额外赔付分开，不重复冲减。
- `resolution` 为 COMPLETE、CANCEL_REFUND、PARTIAL_REFUND_COMPENSATION、REFULFILL；`adjustmentDecisions` 为 `{adjustmentId, decision: CONTINUE|CANCEL, reason}` 数组。已实收不能靠CANCEL删除付款，必要退款仍走M45-04。
- `allocationLines` 为 `{taskId,courierId,amountCents}`；风险 `subject` 为 `{beneficiaryType: PLATFORM|COURIER,beneficiaryId: string|null}`。所有明细必须属于URL订单，拒绝跨单凭证、任务、支付、冻结、售后和调整引用；数据层复合外键或服务事务断言覆盖同单关联，不能只检查各ID存在。
- `order` 响应至少含 id、orderNo、flowVersion、rawStatus、displayStatus、version、originalFeeCents、effectiveFeeCents、deliveredAt、confirmStartedAt、confirmDeadline；时间未发生为null。`account` 不返回密码摘要、微信敏感值或MFA秘密。任务和财务响应按模型字段白名单输出，不直接序列化ORM实体。
- 付款登记、退款、赔付、免债及结案的理由与操作者进入审计metadata；调账只追加事件/流水。部署阶段审计动作和目标类型按版本先扩容，不能让业务已执行而审计失败被忽略。
