# 本地开发与验证

版本：2026-10-25

## 1. 本地边界

本地使用隔离测试数据库、合成用户及测试配置。阶段一生产 v1、v2 停止建单，不能把当前指向生产的旧客户端当新 v2 测试客户端。模拟支付及管理员付款仅在本地/测试/预发布启用；真实身份联调使用受控 AppSecret，不能写入仓库。

以下命令基于当前交接代码，描述可复现检查入口，不代表 v2、模拟适配器或新状态模型已经实现。源代码未修改、未运行命令时均须报告未验证。原有 Compose 可用于旧后端联调，完成 v2 改造后才能验收新规则。

## 2. 必测场景

- 九种服务按分验证：LOBBY 200、DOOR 300、EXPRESS 500；包裹六档 100/200/300/400/500/800。梅园包裹加 200、其他区域加 0；非包裹不加区域费。校验报价持久化、区域启停、价格快照和前端篡改拒绝，不能只测前三档。
- 待支付订单仅用户可见，可重试或取消；骑手列表不可见。
- 模拟支付成功、处理中、失败、未知、重复回调和迟到支付。
- 每单取件凭证必做；规格核验照片只在调整时要求；重派只检查取件凭证。
- 待接单用户主动调整、骑手接单后调整、管理员审核、补款和降档退款。
- 调整期间主履约状态不被覆盖，补款前用户看不到送达照片和位置。
- 送达照片和一次送达位置均成功后记录送达时间；十分钟自动完成与异议并发竞争。
- 到场补贴 100 分：取消前打卡、取消后引用，以服务端时间校验 100 米和 30 分钟；缺坐标、伪造时间、重复申请、已取件均不能自动发放。到场/送达分别存事件，不互相覆盖。
- 已完成订单可进入受控售后，但不可继续履约写入。
- 未取件重派、已取件管理员交接、旧骑手只读。
- 历史 `/api/v1` 订单和旧支付退款任务仍可收尾。

## 4. 已核对的本地命令（PowerShell）

要求 JDK 17、Maven、管理端锁文件对应的 pnpm、Docker Desktop 及 PowerShell 7.2+。下面只用于本地合成数据，未在此次文档修订执行。

### 管理端

工作目录：`D:/biancheng/RunRunCampus/handover-2026-10-24/RunRunCampusAdmin`。

```powershell
pnpm install --frozen-lockfile
pnpm build
pnpm dev
```

实际 package.json 只有 dev/build/preview，没有 pnpm test、pnpm lint。角色 QA 入口是 tools/run-admin-role-qa.ps1、tools/admin-role-qa.cjs；运行前读脚本参数和所需浏览器依赖，不把未执行 QA 记成通过。管理端 dist 需先构建供后端打包或 Compose 挂载。

### 后端测试与打包

工作目录：`D:/biancheng/RunRunCampus/handover-2026-10-24/RunRunCampusBackend`。

```powershell
mvn test
mvn clean package
mvn clean package -DskipTests
```

前两项包含测试，其中 Testcontainers 集成测试使用 postgres:16-alpine：Docker Desktop 须可用，首次需拉镜像；不必先启动 Compose。最后一项跳过测试，仅构建不能证明验收通过。Docker 不可用导致集成失败须如实记录，不删测试绕过。

### 完整 Compose 联调

同一后端目录，先完成管理端构建。用本地合成管理员填写当前 PowerShell 会话环境，手机号和密码必填，显示名有默认值。覆盖文件不自动读取 TEST_ADMIN 名称为应用配置，必须按三文件组合启动。

```powershell
$env:TEST_ADMIN_PHONE = Read-Host '本地合成管理员手机号'
$env:TEST_ADMIN_PASSWORD = Read-Host '本地专用测试密码'
$env:TEST_ADMIN_DISPLAY_NAME = '本地测试管理员'
./tools/new-admin-mfa-key.ps1 -OutputDirectory ./secrets/admin-mfa
docker compose -p runrun-docs-local -f compose.yml -f compose.admin-mfa.yml -f compose.local-test.example.yml up --build
```

MFA 脚本实际位于 tools/，默认输出文件与 compose.admin-mfa.yml 的 ./secrets/admin-mfa/ADMIN_MFA_KEY 对应。脚本拒绝已存在目录：已有正确测试密钥则不要重复生成；需新密钥时换新受保护目录，并用 ADMIN_MFA_KEY_FILE 指向新文件。不得打印密钥或提交 secrets。基础 Compose 的默认数据库口令只适用于隔离本地环境，不可公开部署。首次启动前确认本机端口、现有容器和测试卷，-p 隔离项目名不隔离宿主机端口。

停止本次本地环境，不删除数据卷：

```powershell
docker compose -p runrun-docs-local -f compose.yml -f compose.admin-mfa.yml -f compose.local-test.example.yml down
```

不使用 down -v 清空证据或其他环境。新模拟适配器、v2 配置和营业校验尚需实现；不能凭旧 Compose 启动成功认定新流程可用。

## 5. 补充验收矩阵

| 范围 | 必测场景与断言 |
|---|---|
| 账号 | 微信手机号注册；普通用户恢复旧账号且历史订单归属正确；重复/冲突绑定拒绝；未审核骑手不能接单；骑手及管理员不能自助恢复；密码登录保留 |
| 环境及时间 | 生产 v1 410、v2 停单但历史可收尾；测试 v2 新建单；北京时间 08:59:59 拒绝、09:00 允许、22:59:59 允许、23:00 拒绝；闭店后既有订单仍支付/接单/履约 |
| 付款一致性 | 成功付款同事务变待接单；并发关单/回调；同键异参拒绝；失败后新尝试不续期；未知先查原单；重复成功不重复分账；不同调整单可分别补款 |
| 审核 | 审核中允许配送；两小时有实际接收者、24 小时到值班负责人；不自动拒绝；负责人可关闭未决调整按原价；与审批及完成并发无双重结果 |
| 补款窗口 | 审核通过起 15 分钟但不自动取消；配送任务结束不占名额；未补款不开放凭证、不自动完成；送达及结清后完整十分钟，实际送达时间不被覆盖 |
| 售后与通知 | 一般售后登记即阻止自动完成并冻结该单全部未发权益，多案未决不提前释放；重大异常不因欠款拒绝核查；微信发送失败仍有站内消息且窗口不延期；异议入口一步可达 |
| 结案还款 | 补款逾期超过 30 天管理员结案转欠款，不伪记支付；之后还款不重开窗口；旧凭证已删除时准确提示，不生成假地址 |
| 分账退款 | 送达十分钟无异议原款可日结；降档同比例冲减该单，已发款人工应收、退款不等追偿；责任金额守恒；不自动扣未来日结；普通风险不冻结，管理员确认才冻结 |
| 重新履约 | 调整和补款由管理员一起裁定；新任务邀请原骑手须同意和容量；旧任务不恢复写权限，必要时交接 |
| 数据与权限 | 流程版本不可改；v2 访问历史拒绝；新表无历史业务回填；未授权不可读照片；补款前所有读取路径均隐藏送达凭证 |
| 保留与审计 | 普通完成后 7 天、待补款结清后 7 天；追偿中结案不删证据，正式结束并无争议后 7 天；补贴证据至审核结算后 7 天；action 和 target_type 新值均能落库；删除与保全可审计 |

## 9. 本轮开发规则补齐验收

以下均为待实现验收断言，不表示已运行源码或运行时测试；唯一技术定义见[数据模型与接口契约](数据模型与接口契约.md)C01、M44、A36–A40。

| 范围 | 必测断言 |
|---|---|
| 两种版本 | 新订单流程版本固定且不可改；聚合并发版本从0随成功写递增，旧expectedVersion拒绝且不写副作用；幂等重放不重复增版 |
| 送达后有限权限 | 有效送达骑手仅能申请调整、上传规格证据；不能再取件/送达/定位且不占容量；释放/交接/被替代旧骑手及异常/完成/取消订单拒绝；照片上传本身不阻塞完成 |
| 完成竞争 | 完成先提交则调整拒绝；调整先提交则窗口失效，结清后完整十分钟；实际送达时间不变，不能通过旧上传票据绕过状态检查 |
| 本人任务与混合历史 | 重新登录能找回OFFERED/ACTIVE及已结束任务；v1/v2同ID不串；同单多任务只出一行、先授权去重后分页；仅可证实旧关联可见，旧单不暴露新流程写入口 |
| 骑手数据边界 | 他人任务/证据/结算不可见；已释放/交接骑手只读本人阶段；无资格可读本人资质/历史但不能接单，骑手版不泄露用户独立欠款和支付单细节 |
| 新注册与旧恢复 | 新COURIER可获未审账号及会话、不能直接接单；匹配旧高权限账号走人工；普通旧用户恢复规则保持 |
| 资质申请与照片 | 仅本人PENDING申请可上传真JPEG/PNG且≤8MiB；伪造类型/超限/他人/旧轮照片拒绝；PENDING重复申请冲突；批准必须有本轮有效照片，驳回理由必填 |
| 共享资格与审核竞争 | v1/v2共用行及锁；换图/重申请/旧入口审核均递增版本、使旧审批失效；同键重放无重复对象/审核；已批准重申请保留资格，状态与eligible分开 |
| 学生证读取与清理 | 启用管理员才可读取，no-store且审计成功后交付；审核后30天、资质保全优先；旧入口换图/清理不能旁路删除；删除失败可重试，已删提示准确且不撤销接单资格 |
| 迁移兼容 | V44只扩共享资质列，不复制历史资质或新建历史任务；原资格与照片引用守恒；新旧服务一起接入增版及清理约束；各版审计双白名单支持新增动作 |
