# 跑跑代取运营后台

当前后台包含管理员登录、运营总览、订单管理、骑手管理、用户目录、异常工单中心、意见反馈和操作日志：

- 运营总览集中展示订单、用户、骑手、认证和异常工单指标，并提供快捷处理入口。
- 订单支持分页、搜索、状态筛选、CSV 数据导出与完整详情核查；单次最多导出 10,000 条。
- 骑手支持认证状态筛选、认证资料查看、通过和带原因驳回。
- 用户目录支持账号检索、角色筛选、账号停用和恢复；管理员账号受保护。
- 异常工单支持全局检索、领取、提交处理结果，并可跳转到关联订单详情。
- 意见反馈支持按类型和处理状态检索、领取并提交处理结果。
- 操作日志记录骑手认证、用户账号和异常工单操作，支持按管理员或操作类型检索。

管理员按超级管理员、运营、客服、审核和审计岗位分权；超级管理员可创建后台账号、调整其他管理员岗位，在人员离岗时停用账号，或重置其他管理员密码；这些操作都会注销目标账号的现有会话。

所有管理员均可从侧边栏修改自己的密码；修改成功后必须使用新密码重新登录。

五岗位均强制使用密码和 TOTP 双因素登录。首次登录本地生成绑定二维码，确认动态码后仅展示一次 10 个恢复码；勾选保存后进入后台。侧栏“认证器”支持验证密码与第二因素后换绑；超级管理员可在人工核验后重置其他岗位的认证器，并交付 24 小时有效的重新绑定凭证。超级管理员离线恢复与密钥准备见 [后端 MFA 说明](../RunRunCampusBackend/deploy/ADMIN_MFA.md)。

超级管理员可在用户目录或管理员账号页查看登录锁定状态，并在核实身份后提前解除锁定；解锁操作会进入审计日志。

## 五岗位权限验收

使用 `tools/run-admin-role-qa.ps1` 可在一次性 PostgreSQL、V17 候选后端及真实 Edge 浏览器中验证五种岗位的 MFA 绑定、菜单、按钮、接口权限、实际操作和会话撤销，并覆盖恢复码登录、换绑和人工重置。脚本只使用合成账号，前端构建写入报告目录，不更新当前 `dist` 或运行服务。

前提：Docker Desktop、PowerShell 7.2+、Microsoft Edge、Codex 附带 Node/Playwright，以及已存在的 `runrun-campus-backend:admin-mfa-20260903` 镜像（可用 `-BackendImage` 指定其他已构建 MFA 候选镜像）。测试固定使用本机 28180 端口和专用测试容器名称，因此请串行运行。

```powershell
pwsh -NoProfile -File tools/run-admin-role-qa.ps1 -ReportDirectory 'D:/AdminRoleQaResults/run-1'
```

报告目录必须不存在。成功生成 `acceptance.json`、截图、CSV 和 `run-summary.json`；测试失败也会尝试按资源标签核对并清理本轮容器、临时数据库卷及网络，保留失败日志。正常完成后 `success` 和 `cleanupComplete` 均为 `true`。

## 管理员账号

后端通过以下环境变量初始化管理员账号：

- `APP_ADMIN_PHONE`：管理员手机号
- `APP_ADMIN_PASSWORD`：管理员密码
- `APP_ADMIN_DISPLAY_NAME`：管理员显示名称，可选

手机号与密码均未配置时，后端不会自动创建管理员。若手机号已属于普通用户或骑手，后端也不会自动提升其权限。

## 本地运行

先启动 `RunRunCampusBackend`，确保后端监听 `http://127.0.0.1:8080`，然后执行：

```powershell
pnpm install
pnpm dev
```

开发服务器会将 `/api` 代理到本地后端。生产环境建议由同一 HTTPS 域名反向代理后台静态文件和 `/api`，因此不需要开放跨域访问。

如需单独配置 API 地址，创建 `.env.local`：

```text
VITE_API_BASE_URL=https://api.example.com
```

不要在前端环境变量中保存管理员密码、数据库密码或云服务密钥。

## 持久运行

后台生产构建挂载到现有 API 容器，由 Spring Boot 持久提供。在本目录更新代码后先执行 `pnpm build`，然后在 `RunRunCampusBackend` 目录执行：

```powershell
docker compose -f compose.yml -f compose.admin-mfa.yml up --detach --build api
```

后台地址为 `http://127.0.0.1:5173`。生产构建以只读方式挂载到容器，后台和 API 使用同一服务，不依赖临时 Vite 进程。容器使用 `unless-stopped` 重启策略；Docker Desktop 启动后，PostgreSQL、API 和后台会自动恢复。后台端口仅绑定本机，不向局域网开放。
## v1.9 运营指挥台

指挥台支持待接 10 分钟、接单后 30 分钟未完成的预警队列，按停留时间排序并直达订单详情；在线运力显示已上线骑手和进行中单量。预警与运力默认每 30 秒刷新，可暂停；待办统计使用独立的“刷新待办统计”按钮。请求失败时保留上次成功快照并显示数据时间和错误提示。

待审认证、待领取和处理中的异常/反馈卡片会直接打开对应筛选列表。各分区保留既有岗位权限。

配套接口 `/api/v1/admin/command-center` 需要 v1.9 后端。页面时限为运营提醒，历史记录缺失的订单标注“估算”。在线状态为骑手主动接单开关，不表示实时定位。

浏览器验收脚本：`tools/command-center-qa.cjs`。在 `127.0.0.1:5179` 运行 Vite，提供 Playwright 模块与 Edge 后执行 `node tools/command-center-qa.cjs`。脚本拦截全部 API，使用合成账户/订单，验证队列、分页、详情、筛选跳转、权限分区、刷新与失败状态，并输出桌面/窄屏截图。
