# 测试环境地址与启动说明

## 当前状态

截至 2026-10-24，没有发现已经建立并与生产隔离的公网测试环境或测试域名。

目前可交付的是本地测试环境：

|用途|地址|
|-|-|
|后端 API 基地址|`http://127.0.0.1:8080`|
|后端健康检查|`http://127.0.0.1:8080/api/v1/health`|
|管理端开发地址|`http://127.0.0.1:5173`|
|本地 PostgreSQL|`127.0.0.1:5432`，仅限本机|

正式环境地址仅用于版本核验，不属于测试环境：

|用途|地址|
|-|-|
|正式 API 基地址|`https://api.runruncampus.cn`|
|正式健康检查|`https://api.runruncampus.cn/api/v1/health`|
|正式管理端|`https://api.runruncampus.cn/`|

2026-10-24 核验时，正式健康检查返回 HTTP 200 和 `{"status":"ok"}`。未经项目所有者明确授权，协作者不得使用正式环境进行开发测试、创建测试订单或修改数据。

## 本地测试环境启动步骤

前提：Windows PowerShell、Docker Desktop、Node.js 和 pnpm。

1. 进入 `RunRunCampusAdmin`。
2. 执行 `pnpm install`。
3. 执行 `pnpm build`，生成 `dist`。后端 Compose 会只读挂载这个目录。
4. 进入 `RunRunCampusBackend`。
5. 首次运行时执行 `./tools/new-admin-mfa-key.ps1 -OutputDirectory './secrets/admin-mfa'`，生成本地测试用 MFA 密钥。不得复制生产密钥。
6. 在当前 PowerShell 会话中设置三个合成测试管理员环境变量：`TEST_ADMIN_PHONE`、`TEST_ADMIN_PASSWORD`、`TEST_ADMIN_DISPLAY_NAME`。不得使用真实生产管理员资料。
7. 执行：

   `docker compose -f compose.yml -f compose.admin-mfa.yml -f compose.local-test.example.yml up --build`

8. 等待后端启动后访问健康检查地址，必须返回 `{"status":"ok"}`。
9. 打开管理端地址，使用刚才设置的合成测试管理员账号完成首次 MFA 绑定。
10. 确认 Flyway 已执行到 V43，再开始功能开发。

## 测试账号交付规则

本资料包不放置真实管理端账号。协作者应在本地通过环境变量初始化合成测试管理员；如以后建立远程测试环境，测试账号由项目所有者通过私密渠道单独交付，并与生产账号完全隔离。

## 建议的远程测试环境

如需要多人联调，可另行建立独立测试域名、独立数据库、独立对象存储目录和独立微信支付沙箱或测试方案。建议地址可以采用 `https://test-api.runruncampus.cn`，但该地址目前只是命名建议，尚未配置，不能写成已可访问的测试地址。
