# 小程序接口清单

基线日期：2026-10-22

## 1. 通用约定

- 基础地址：`<ISOLATED_TEST_API_BASE_URL>`
- 普通请求：JSON
- 文件上传：`multipart/form-data`，文件字段名固定为 `file`
- 登录后鉴权：`Authorization: Bearer <token>`
- 请求超时：普通请求 15 秒，文件上传 30 秒
- 创建订单：请求头携带 `Idempotency-Key`
- 401 响应：客户端清除本地会话；后续开发应补充统一跳转登录页和过期提示

## 2. 认证与隐私

| 方法 | 路径 | 调用方 | 用途 |
| --- | --- | --- | --- |
| GET | `/api/v2/privacy/policy` | 未登录 | 获取当前隐私政策 |
| POST | `/api/v2/privacy/consent` | 已登录 | 记录用户同意的政策版本 |
| POST | `/api/v2/auth/captcha` | 未登录 | 获取登录验证码挑战 |
| POST | `/api/v2/auth/wechat/bind-phone` | 未登录 | 手机号、密码、昵称、角色注册 |
| POST | `/api/v2/auth/password/login` | 未登录 | 手机号和密码登录，必要时附验证码 |
| POST | `/api/v2/auth/logout` | 已登录 | 注销当前会话 |

客户端约定注册角色为 `CUSTOMER` 或 `COURIER`。注册和登录请求携带 `clientType: WECHAT_MP` 与设备名称；成功响应应包含 `token` 和 `user`。

## 3. 服务配置与订单

| 方法 | 路径 | 调用方 | 用途 |
| --- | --- | --- | --- |
| GET | `/api/v2/service-config` | 已登录或公开 | 校区、营业时间、取件点、配送区 |
| POST | `/api/v2/orders` | 用户 | 发布订单 |
| GET | `/api/v2/orders` | 用户/骑手 | 当前账号进行中订单 |
| GET | `/api/v2/order-history?limit=50` | 用户/骑手 | 当前账号历史订单 |
| GET | `/api/v2/courier/order-pool` | 已认证骑手 | 可接订单 |
| GET | `/api/v2/orders/{id}` | 订单相关方 | 订单详情 |
| POST | `/api/v2/orders/{id}/accept` | 骑手 | 接单 |
| POST | `/api/v2/orders/{id}/cancel` | 用户 | 取消待接订单 |
| POST | `/api/v2/orders/{id}/pickup` | 骑手 | 确认已取件 |
| POST | `/api/v2/orders/{id}/release` | 骑手 | 无法履约并申请重新派单 |
| POST | `/api/v2/orders/{id}/locations` | 骑手 | 主动上传当前位置 |
| GET | `/api/v2/orders/{id}` | 用户 | 查看订单详情及服务端允许的收货信息 |
| POST | `/api/v2/orders/{id}/deliver` | 骑手 | 使用收货码完成订单 |

创建订单主要字段：

- `merchant`：商户或包裹来源名称
- `pickupCode`：取件凭据
- `pickupLocation`：取件点展示名称
- `destination`：具体送达位置
- `serviceType`：服务类型
- `pickupStation`：取件点代码
- `deliveryZone`：配送区代码
- `couponId`：当前固定为 `null`
- `useMembership`：当前固定为 `false`

服务类型：

- 外卖：`LOBBY`、`DOOR`、`EXPRESS`
- 快递：`PACKAGE_SMALL`、`PACKAGE_MEDIUM`、`PACKAGE_MEDIUM_LARGE`、`PACKAGE_LARGE`、`PACKAGE_EXTRA_LARGE`、`PACKAGE_XL`

客户端已识别的订单状态：`PENDING_ASSIGNMENT`、`PENDING_REASSIGNMENT`、`ACCEPTED`、`PICKED_UP`、`COMPLETED`、`CANCELLED`。如果后端增加状态，需要同时补充显示文案和操作权限。

## 4. 快递规格与凭证

| 方法 | 路径 | 调用方 | 用途 |
| --- | --- | --- | --- |
| POST | `/api/v2/orders/{id}/adjustments` | 骑手 | 提交现场包裹规格 |
| POST | `/api/v2/orders/{id}/confirm` | 用户 | 确认订单或调整结果 |
| POST | `/api/v2/orders/{id}/cancel` | 用户 | 拒绝调整并取消订单 |
| POST 上传 | `/api/v2/orders/{id}/uploads` | 骑手 | 规格核验照片 |
| POST 上传 | `/api/v2/orders/{id}/uploads` | 骑手 | 取件凭证 |
| POST 上传 | `/api/v2/orders/{id}/uploads` | 骑手 | 送达凭证 |

后端必须校验文件类型、大小、订单归属和当前状态。前端按钮条件不能作为安全边界。

## 6. 支付与通知

| 方法 | 路径 | 调用方 | 用途 |
| --- | --- | --- | --- |
| POST | `/api/v2/payments/{id}/attempts` | 用户 | 创建支付尝试；金额和支付方式以后端支付单为准 |
| GET | `/api/v2/payments/{id}` | 用户 | 查询支付状态 |
| POST | `/api/v2/payments/{id}/query` | 用户 | 查询未知支付结果 |
| GET | `/api/v2/notifications` | 用户 | 查询站内通知 |
| POST | `/api/v2/notifications/{id}/read` | 用户 | 标记通知已读 |

阶段一仅在隔离 local/test/staging 环境允许显式开启 MOCK 支付。客户端不展示个人收款码、不接受线下付款凭据，也不把 `wx.requestPayment` 成功当作到账事实；生产支付保持关闭。
