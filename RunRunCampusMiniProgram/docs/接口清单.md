# 小程序接口清单

基线日期：2026-10-22

## 1. 通用约定

- 基础地址：`https://api.runruncampus.cn`
- 普通请求：JSON
- 文件上传：`multipart/form-data`，文件字段名固定为 `file`
- 登录后鉴权：`Authorization: Bearer <token>`
- 请求超时：普通请求 15 秒，文件上传 30 秒
- 创建订单：请求头携带 `Idempotency-Key`
- 401 响应：客户端清除本地会话；后续开发应补充统一跳转登录页和过期提示

## 2. 认证与隐私

| 方法 | 路径 | 调用方 | 用途 |
| --- | --- | --- | --- |
| GET | `/api/v1/privacy/policy` | 未登录 | 获取当前隐私政策 |
| POST | `/api/v1/privacy/consent` | 已登录 | 记录用户同意的政策版本 |
| POST | `/api/v1/auth/captcha` | 未登录 | 获取登录验证码挑战 |
| POST | `/api/v1/auth/register` | 未登录 | 手机号、密码、昵称、角色注册 |
| POST | `/api/v1/auth/login` | 未登录 | 手机号和密码登录，必要时附验证码 |
| POST | `/api/v1/auth/logout` | 已登录 | 注销当前会话 |

客户端约定注册角色为 `CUSTOMER` 或 `COURIER`。注册和登录请求携带 `clientType: WECHAT_MP` 与设备名称；成功响应应包含 `token` 和 `user`。

## 3. 服务配置与订单

| 方法 | 路径 | 调用方 | 用途 |
| --- | --- | --- | --- |
| GET | `/api/v1/service-config` | 已登录或公开 | 校区、营业时间、取件点、配送区 |
| POST | `/api/v1/orders` | 用户 | 发布订单 |
| GET | `/api/v1/orders/mine/active` | 用户/骑手 | 当前账号进行中订单 |
| GET | `/api/v1/orders/mine/history?page=0&size=50` | 用户/骑手 | 当前账号历史订单 |
| GET | `/api/v1/orders/available` | 已认证骑手 | 可接订单 |
| GET | `/api/v1/orders/{id}` | 订单相关方 | 订单详情 |
| GET | `/api/v1/orders/{id}/events` | 订单相关方 | 订单事件时间线 |
| POST | `/api/v1/orders/{id}/accept` | 骑手 | 接单 |
| POST | `/api/v1/orders/{id}/cancel` | 用户 | 取消待接订单 |
| POST | `/api/v1/orders/{id}/pickup` | 骑手 | 确认已取件 |
| POST | `/api/v1/orders/{id}/unable` | 骑手 | 无法履约并申请重新派单 |
| POST | `/api/v1/orders/{id}/location` | 骑手 | 主动上传当前位置 |
| GET | `/api/v1/orders/{id}/delivery-code` | 用户 | 查看六位收货码 |
| POST | `/api/v1/orders/{id}/complete` | 骑手 | 使用收货码完成订单 |

创建订单主要字段：

- `merchant`：商户或包裹来源名称
- `pickupCode`：取件凭据
- `pickupLocation`：取件点展示名称
- `destination`：具体送达位置
- `serviceType`：服务类型
- `pickupStation`：取件点代码
- `deliveryZone`：配送区代码
- `couponId`：当前固定为 `null`
- `useMembership`：当前固定为 `false`

服务类型：

- 外卖：`LOBBY`、`DOOR`、`EXPRESS`
- 快递：`PACKAGE_SMALL`、`PACKAGE_MEDIUM`、`PACKAGE_MEDIUM_LARGE`、`PACKAGE_LARGE`、`PACKAGE_EXTRA_LARGE`、`PACKAGE_XL`

客户端已识别的订单状态：`PENDING_ASSIGNMENT`、`PENDING_REASSIGNMENT`、`ACCEPTED`、`PICKED_UP`、`COMPLETED`、`CANCELLED`。如果后端增加状态，需要同时补充显示文案和操作权限。

## 4. 快递规格与凭证

| 方法 | 路径 | 调用方 | 用途 |
| --- | --- | --- | --- |
| POST | `/api/v1/orders/{id}/package-size` | 骑手 | 提交现场包裹规格 |
| POST | `/api/v1/orders/{id}/package-size/approve` | 用户 | 同意规格调整 |
| POST | `/api/v1/orders/{id}/package-size/reject` | 用户 | 拒绝规格调整并取消订单 |
| POST 上传 | `/api/v1/orders/{id}/proofs/SIZE_REVIEW` | 骑手 | 规格核验照片 |
| POST 上传 | `/api/v1/orders/{id}/proofs/PICKUP` | 骑手 | 取件凭证 |
| POST 上传 | `/api/v1/orders/{id}/proofs/DELIVERY` | 骑手 | 送达凭证 |

后端必须校验文件类型、大小、订单归属和当前状态。前端按钮条件不能作为安全边界。

## 5. 骑手认证与运营状态

| 方法 | 路径 | 调用方 | 用途 |
| --- | --- | --- | --- |
| GET | `/api/v1/courier-certification/me` | 骑手 | 查询本人认证状态 |
| POST | `/api/v1/courier-certification/apply` | 骑手 | 提交认证申请 |
| POST 上传 | `/api/v1/courier-certification/{id}/student-card` | 骑手 | 上传学生证照片 |
| GET | `/api/v1/courier/operations/me` | 已认证骑手 | 接单状态和经营数据 |
| PUT | `/api/v1/courier/operations/me/availability` | 已认证骑手 | 上线或暂停接单 |

客户端已识别的认证状态：`NOT_APPLIED`、`PENDING`、`APPROVED`、`REJECTED`。

## 6. 人工核款

| 方法 | 路径 | 调用方 | 用途 |
| --- | --- | --- | --- |
| POST | `/api/v1/orders/{id}/manual-payment/request` | 骑手 | 到达后通知用户付款 |
| POST | `/api/v1/orders/{id}/manual-payment/submit` | 用户 | 提交付款昵称或手机号后四位 |

客户端展示 `images/wechat-personal-qr.jpg`，并等待管理员在现有运营后台确认到账。订单支付方式为 `PERSONAL_QR_MANUAL` 时，只有后端返回 `paymentStatus: PAID` 后，客户端才允许骑手完成配送。

交接前必须确认该二维码仍属于授权收款人。更换收款主体时，要同步替换图片、提示文案、隐私说明和后台核款流程。

## 7. 当前公开接口抽查

- `/api/v1/service-config`：可访问，当前校区为无锡学院

此清单来自当前客户端实际调用。后端接口文档、数据库模型和管理员接口不在本小程序源码中，合作者仍需取得对应后端仓库或 OpenAPI 文档。
