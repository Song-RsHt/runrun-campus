## P0：核心流程验收

### 账号和隐私

- [ ] 首次进入能加载隐私政策；未勾选时不能注册或登录。
- [ ] 用户和骑手都能注册、登录、退出并重新登录。
- [ ] 三次错误密码后验证码流程可用。
- [ ] 会话失效时清除本地凭据，并明确跳转登录页。
- [ ] AppSecret、管理员凭据和后端密钥不会出现在前端包或日志中。

### 用户下单

- [ ] 外卖订单可选择取件点、配送区和服务类型并成功发布。
- [ ] 快递订单六档规格价格与后端配置一致。
- [ ] 用户选择规格并确认后直接调起微信支付，金额始终以后端计算结果为准。
- [ ] 后端确认支付成功后订单才进入骑手可接单池。
- [ ] 连续点击提交不会创建重复订单。
- [ ] 用户可看到进行中订单、历史订单和事件时间线。
- [ ] 待接订单可取消，已接订单不能越权取消。

### 骑手认证和接单

- [ ] 骑手可申请认证并上传学生证照片。
- [ ] 取消拍照或上传失败后能够重新上传，不留下无法继续的状态。
- [ ] 未审核骑手不能上线或接单。
- [ ] 已审核骑手可上线、暂停、查看可接订单并接单。
- [ ] 未支付、支付中或支付结果未知的订单对骑手不可见且不能被接口接取。
- [ ] 两名骑手同时抢同一订单时只允许一人成功。

### 支付和履约

- [ ] 取件前必须上传取件凭证。
- [ ] `wx.requestPayment` 成功后仍由后端回调或主动查单确认最终支付状态。
- [ ] 用户取消支付、支付超时、回调延迟和重复通知均有明确且幂等的处理结果。
- [ ] 快递实际规格变化时必须上传核验照片；升档走补差价支付，降档走部分退款。
- [ ] 骑手位置授权拒绝、再次授权和更新成功的提示清晰。
- [ ] 补差价未确认到账前骑手不能确认取件，退款状态在用户端可查询。
- [ ] 送达前必须上传送达凭证，错误收货码不能完成订单。
- [ ] 完成后用户和骑手看到一致的订单状态与事件时间线。
- [ ] 骑手申请重新派单后，订单能被其他骑手接取。

### 权限与安全

- [ ] 用户不能调用骑手专属接口，骑手不能操作无关订单。
- [ ] 修改订单 ID 不能读取他人的地址、凭证、付款或收货码。
- [ ] 上传接口限制文件类型、大小、订单归属和访问权限。
- [ ] 日志不记录密码、完整 Token、收货码、学生证图片地址或完整手机号。
- [ ] HTTPS 证书链和域名配置在真机环境正常。

## P1：提交审核前建议修复

- [ ] 在请求层集中处理 401：提示会话过期并跳转登录页。
- [ ] 为网络超时、离线、重复提交和上传失败提供明确重试入口。
- [ ] 历史订单从固定 50 条改为分页或触底加载。
- [ ] 对上传图片增加前端大小、类型提示，并压缩大图。
- [ ] 明确位置权限被永久拒绝后的设置页引导。
- [ ] 检查全面屏、深色模式、字体放大和低端机布局。
- [ ] 为新增后端状态提供兜底文案和可观测日志。
- [ ] 建立接口契约测试，避免后端字段变化导致页面静默失效。
- [ ] 确认是否需要订阅消息；如果需要，应单独设计授权时机和消息模板。

## 发布门槛

只有同时满足以下条件，才能认为“小程序开发完成”：

1. P0 项全部完成并留存测试证据。
2. 正式 AppID 下编译、预览和真机调试通过。
3. 用户、骑手、管理员三方完整订单至少成功走通一次。
4. 微信公众平台隐私保护指引、服务器域名、服务类目和名称审核通过。
5. 生产监控、客服联系人、异常订单处理和回滚负责人明确。
6. 上传审核版本与 Git 标签或提交哈希一一对应，可重复构建。
