# 跑跑代取微信小程序

这是复用现有跑跑校园后端的微信原生小程序首版，产品名称已确定为“跑跑代取”，包含用户端和骑手端主流程。

交给其他开发者继续开发前，请先阅读：

- [`docs/项目交接说明.md`](docs/项目交接说明.md)
- [`docs/接口清单.md`](docs/接口清单.md)
- [`docs/后续开发与验收清单.md`](docs/后续开发与验收清单.md)
- [`docs/合作者开发任务清单.md`](docs/合作者开发任务清单.md)

## 已实现

- 手机号注册、登录与登录验证码
- 用户发布外卖/快递代取订单
- 用户查看进行中和历史订单、取消待接订单
- 快递规格现场确认、用户同意或拒绝规格调整
- 骑手认证材料上传、上线/暂停接单、查看并接取订单
- 取件/送达凭证上传、位置主动更新、收货码完成订单
- 现有个人收款码人工核款流程：骑手通知付款、用户提交核款备注、等待管理员确认
- 本地会话保存和退出登录

没有新增微信授权登录、会员、优惠券、聊天、管理员审核或新的支付方式。

## 导入运行

1. 安装并打开微信开发者工具。
2. 选择“导入项目”，目录选择本文件夹。
3. `project.config.json` 已配置正式小程序 AppID；开发者需要先被管理员加入该小程序的项目成员。
4. 开发工具中若使用游客模式，可在本地调试阶段关闭合法域名校验。
5. 正式小程序后台需要把 `https://api.runruncampus.cn` 配置为 request 与 uploadFile 合法域名。

API 地址集中在 `utils/api.js` 的 `BASE_URL`。不要把 AppSecret、登录密码或其他密钥写进小程序源码。

## 上线前必须完成

- 在微信公众平台填写小程序名称、类目、服务内容和隐私保护说明。
- 根据实际功能声明手机号、位置、相机/相册、校园身份材料和支付信息的处理目的与保存规则。
- 用正式 AppID 在微信开发者工具中完成真机调试和上传审核。
- 分别用用户账号和已审核骑手账号走通：注册/登录 → 选择规格 → 确认金额 → 微信支付 → 骑手接单 → 取件凭证 → 送达凭证 → 收货码完成。
- 微信支付正式切换前保留现有人工核款能力作为应急回退；正式发布包不得向新订单展示个人收款码。
